# KClevoPanel 0.11：风扇控制完善

本版将30秒曲线试用扩展为可在程序运行期间使用的自定义控制，并增加自动/最大风量入口。主程序仍为原生 WinUI 3。适配范围为当前 COLORFUL X17 AT 23H2 / BIOS 1.07.04TCOLO 和已核对的桥驱动、DriverStore DLL。

## 使用方式

1. 进入「散热控制」，顶部选择自动、最大风量或自定义。
2. 分别调整CPU/GPU的两个中间节点；首尾节点锁定，曲线要求温度与占空比单调，中间占空比至少30%。编辑自动保存本机草稿，尚不控制硬件。
3. 可先「试用30秒」，然后「保持此曲线」；也可直接「应用曲线」。后者在程序运行期间保持，不会在下次开机或启动时自动重放。
4. 「停止并恢复」返回进入前的曲线和风扇模式。最小化/关闭收进托盘后继续控制；托盘菜单真正退出时触发恢复。

自动和最大风量是明确写入的固件模式，退出时不主动撤销。自定义会话采用独立恢复进程；应用心跳中断超过10秒、进程退出、采样间隔异常、睡眠/唤醒通知、异常温度/转速或外部覆盖均触发恢复尝试。恢复未确认时保留记录，阻止继续写入。旧记录先只读比较，不自动重放恢复。

## 实现与本机修正

- 风扇模式使用已静态核对的121/sub1、模式0/1/6及page4/offset5的一字节镜像，不写整页配置。自动/最大模式事务在写入前落盘，失败补偿所捕获的模式。
- 曲线使用普通 `SetDCHU_Data(14,frame,256)`，不使用Ex或尝试其他编号。本机实际返回20/0x14，旧代码错误地要求返回14，导致首次测试报告失败；新实现保留应答数值，以新读的两路各四个节点匹配作为通过条件，再启用Custom6。
- 固件写表后将未使用第三风扇槽从已知占位值规范化为全零。旧解码器把全零判为不支持，使恢复状态无法确认；现只接受已核对的两种空槽，未知活动第三槽继续拒绝。首次测试的原曲线实际已恢复，修正解码后通过完整节点与设置token只读比较解除旧记录，没有为清理记录额外写硬件。
- 初次修正测试还观察到低温固件停转。现区分缺失转速和合法零转速：CPU<55°C、GPU<50°C时允许固件停转，高温零转速仍触发恢复。没有增加手动停转命令。
- 风扇页改为持久只读工作进程，初始化身份后复用通道；每约3秒核对完整状态，保护进程独立约750ms检查。监测暂停不暂停恢复保护。
- 新增模式图标、当前模式、温度/实际转速、应用/恢复提示、试用倒计时、运行期间保持状态和会话诊断。

## 目标机实测

本次明确执行了已核对接口的硬件写入，测试前后均保存原始JSON。没有运行未知命令或安装驱动。

本仓库收录[验证摘要](evidence/v0.11/summary.json)、[窗口验证摘要](evidence/v0.11/ui-smoke.json)与[自动检查记录](evidence/v0.11/self-tests.txt)。原始逐次实机JSON另随v0.11验证材料交付，不包含在本仓库；摘要已比较前后两路节点和设置token。

持续控制测试的首次脚本使用PowerShell同步等待整个子进程树，直到守护恢复进程结束才发送保持，导致它正常在30秒结束；修正测试程序为读取工作进程首行应答后立即发送保持，后续验证通过。此为测试驱动时序问题，发布应用本就读取首行应答。

本版窗口检查未启用60秒曲线边界专项及性能档位成功反馈专项；报告中这两项为false表示未运行，本次没有将它们列为通过。风扇页深色、浅色、窄窗口与操作区预览已逐张查看。

## 验证边界

以上转速为本机原厂公式换算的接口读数，未用外部转速计校准。自定义表的逐节点读回已验证；小幅改动测试没有证明完整温度区间的风量、噪声和散热表现。未进行数小时高负载、真实系统睡眠/唤醒、断电或内核驱动挂起测试；睡眠通知钩子和采样中断逻辑已实现。独立进程不能保证在系统故障时完成恢复。

偏移、强冷/除尘、自动开机应用以及原厂完整预设联动暂未开放。风扇写入仅支持指定DriverStore哈希，不覆盖所有性能模式支持的DLL版本。请不要同时用原厂、旧版或其他控制程序更改曲线和模式。

日志保留在 `%LOCALAPPDATA%\KClevoPanel\FanTrials` 与 `FanModes`；草稿只保存本机，不联网上传。恢复失败时不要删除记录强行继续。
