# KClevoPanel 0.11 · WinUI 3 监测与风扇控制

针对 COLORFUL X17 AT 23H2 / i7-13650HX / RTX 4060 Laptop / BIOS 1.07.04TCOLO 的原生 Windows x64 应用。解压完整发布文件夹，运行 KClevoPanel.exe。

## 0.11 风扇控制

「散热控制」提供自动、最大风量、自定义三个带图标的模式按钮。自动交由固件调速；最大风量直接切换已核对的固件模式。这两个模式作为用户明确选择的固件状态，退出程序后不主动改回，也不会在下次启动时重放。

CPU/GPU 曲线分别编辑，支持拖动中间节点或输入温度与占空比、重置编辑和本机草稿。虚线显示实时运行表，首尾节点从本机读取并锁定。草稿路径为 `%LOCALAPPDATA%\KClevoPanel\fan-curve-draft.json`；读取、编辑和保存草稿不写风扇。

- **试用 30 秒**：修改至少一个中间节点后可试用，到时恢复进入前的曲线与风扇模式。试用期间可以「保持此曲线」转为持续控制。
- **应用曲线 / 自定义**：直接在程序运行期间保持。可继续编辑草稿，再次应用时先恢复旧会话、重新读取基线，然后建立新会话。已有相同曲线时只设置自定义模式，不重复写表。
- **停止并恢复**：恢复进入前的曲线和风扇模式。真正退出程序、心跳超过 10 秒未更新、采样中断或睡眠/唤醒事件也触发恢复。最小化/关闭窗口只是收进托盘，持续控制继续运行。
- 独立恢复进程在首次硬件写入前就绪并保存基线；UI 每秒发送心跳，恢复进程约每 750 ms 核对温度、转速、曲线和模式。风扇页使用持久只读工作进程，每约 3 秒核对完整状态，避免反复进行身份查询。普通监测频率设置不暂停控制保护。
- 启动时不自动应用，也不自动重放旧恢复写入。遗留会话先只读比较基线；不一致时提供显式恢复，未确认前阻止新操作。多份遗留记录逐一处理，避免连续重放旧基线。

### 本机协议和保护条件

- 只允许已匹配的机型、BIOS、桥驱动和 DriverStore DLL 哈希 `470D96…3299` 进行风扇写入，不回退其他 DLL，不探测未知命令。
- 曲线采用本机 FanSpeedSetting 6.40 已静态核对的普通 `SetDCHU_Data(14,frame,256)`；模式采用 `SetDCHU_Data(121,{mode,0,0,1},4)`，仅开放 Auto0、Max1、Custom6，镜像只写 `WriteAppSettings(4,5,1,[mode])` 一字节。**不写 AppSettings page4 整页曲线。**
- 本机曲线接口实际返回 **20 / 0x14**，不会把返回数字当作生效证明。每次修改必须新读两路各四个运行时节点逐一匹配，再启用 Custom6；同时记录模式应答121和镜像应答1。本机无第三风扇的保留槽可能被固件规范化为全零，解码接受已核对的两种空槽，拒绝未知活动槽。
- 本机首节点 40°C/raw71；CPU 终点100°C、GPU终点99°C/raw255。中间占空比至少30%，温度与占空比单调；不套用上游两路终点100°C的常量。原厂强冷或风扇偏移非零、DTT或未知模式分支拒绝控制。
- 开始自定义需 CPU<90°C、GPU<82°C；运行中 CPU≥95°C、GPU≥87°C、遥测无效、高温零转速、外部设置覆盖时触发恢复。低温时固件允许停转：CPU<55°C、GPU<50°C 时零RPM不单独判为故障；缺失转速始终拒绝。未增加强制停转命令。
- 曲线恢复逐节点核对，模式恢复核对模式记录。恢复原表失败时尝试交还 Auto0，仍报告恢复未确认并阻止后续控制。重建斜率不等于不可读取的隐藏状态逐字节还原。断电、内核挂起等情况下不能保证恢复。
- 自动/最大模式写入也有独立事务日志；失败只补偿所捕获的风扇模式，不额外改曲线。旧模式事务未完成时只允许显式自动恢复。日志位于 `%LOCALAPPDATA%\KClevoPanel\FanTrials` 和 `FanModes`。
- 自定义控制期间暂禁本版主窗与托盘的性能档位切换。不要与原厂或其他版本同时控制。偏移、强冷/除尘、开机自动应用仍未开放。

### 验证范围

本版已在目标机实际写入并验证：CPU第二节点约52%→55%后两路运行时节点匹配，30秒结束恢复；最大风量约6秒后两路占空比100%，原厂公式换算约6956/6824 RPM，随后恢复原自动模式。持续控制、心跳中断恢复及完整窗口测试结果见随版本发布的验证说明与JSON证据。物理转速未用外部仪器校准，尚未验证数小时高负载、真实系统睡眠/唤醒及强制断电场景。

0.10 为仅提供30秒试用的历史实验版，当时未做实机写入；以上实机结果与持续控制为0.11新增。窗口开发测试严格禁止风扇与性能写入，两种请求计数均应为0。

## 0.9 设置、侧栏与关于

左侧汉堡按钮可展开/收起侧栏，收起后保留导航图标。底部新增设置入口，外观和读取通道不再占用侧栏独立位置。设置包含：

- 主题：跟随Windows、浅色、深色；主窗口与托盘同步。
- 系统与显卡采样间隔：250、500、1000、2000毫秒，默认500。
- 温度与风扇采样间隔：1、2、5秒，默认1秒；独立计时，不随系统间隔变慢，不重叠发起读取。
- 读取通道：默认折叠，展开查看来源、通道状态、DLL路径/哈希和导出。
- 关于：应用标识、真实程序集版本、功能/本地数据说明、适配设备和技术致谢，支持返回设置及浅/深主题。

主题、两组采样间隔和侧栏展开状态保存在 `%LOCALAPPDATA%\KClevoPanel\settings.json`，立即生效，重启恢复；无效值回退默认，保存失败保留本次运行设置。暂停会同时停止两组采样计时器；恢复按当前设置启动。

开发窗口验证不读写用户偏好，使用默认值后检查设置序列化、非法间隔回退、独立采样、导航和侧栏，并保存本程序预览。验证不会发送固件模式写入。

## 0.8 的实际范围

四档按钮改为直接调用已核对的 DCHU 接口，移除原厂菜单辅助功能桥接。无需 FnKey 或 CC40 进程运行。接口库优先使用 Windows 驱动仓库里的已安装版本，不复制或分发原厂二进制；仍需要 ACPI\CLV0001 / CLV0002 驱动及相应DLL。原厂同时运行可能覆盖设置，应避免两边同时操作。

**四档按钮调整固件性能档位，不是原厂完整预设的逐项复刻。** 四档按钮不额外写入风扇模式/曲线、Windows 电源计划或GPU休眠，也不会关闭其他应用。四档保留安静、省电、性能、娱乐的编号映射。界面状态和导出区分命令应答、保存档位与硬件效果，不能把设置镜像读回当作功耗策略的实测证明。

驱动接口/命令与约束：

| 操作 | 接口及参数 | 成功判据 |
| --- | --- | --- |
| 读取原厂保存状态 | ReadAppSettings(1,0,256,output)、(4,0,256,output) | 返回0x1000且保护边界完整 |
| 固件性能档位 | SetDCHU_Data(121,{value,0,0,25},4) | 返回121，仅为命令应答 |
| 保存选中档位 | WriteAppSettings(1,1,1,input) | 返回1；重新读取镜像 |
| 温度与风扇 | GetDCHU_Data_Buffer 12/13 | 固定返回值、字段和保护边界检查 |

基础映射为安静0、省电1、性能2、娱乐3。性能档保留已核对的Turbo标志0x40。DTT不为0、quiet_plus基线、未知增压标志或不匹配机型/BIOS/驱动/DLL均阻止写入；不猜测DTT的0x80分支。

直接模式先检查有效遥测和状态前置条件，写入前把基线与固定计划刷入事务日志。固件应答后同步镜像，读回相关设置。失败时仅尝试一次已验证基线的补偿操作；不会自动重发目标操作。进程崩溃可能来不及补偿，未完成日志将阻止后续模式写入，必须显式恢复。

日志仅在用户切换或显式测试/恢复时写到 `%LOCALAPPDATA%\KClevoPanel\Presets\`；普通周期读取不写日志。启动、窗口测试均不自动切档。

## 设备监测和界面

- 主界面和托盘：四档分段切换，180毫秒选中背景滑动。打开主窗口为小图标，暂停入口保留在托盘右键菜单。
- CPU、内存、GPU、电池60秒网格折线图；按实际时间显示，缺失/暂停留空，不补造样本。
- 系统和NVIDIA默认每500 ms采样，CPU温度/风扇约1秒；显示动画与采样独立。隐藏窗口不运行动画。
- CPU/GPU型号及温度在主窗口、小面板采用相同位置与格式；两路风扇转速/占空比/历史。
- WinUI 3 Mica主窗口、Acrylic小面板，跟随系统/浅/深主题；最小化和关闭收进托盘，退出使用托盘右键。
- 设备信息页：CPU、GPU、内存条、磁盘、主板/BIOS、物理网络适配器、音频、系统。按需后台加载，双列独立堆叠，窄窗口单列。
- 缺失指标显示不可用。内存GiB、磁盘十进制GB/TB；不猜测NVMe/SSD，不显示错误的32位显存容量。
- 未采集序列号、MAC/IP，不联网上传，不创建启动项，不安装驱动。

NVIDIA查询可能唤醒独显。当前仅显示第一块NVIDIA GPU。转速按本机原厂公式换算，未完成外部转速计校准。

优先 Windows/System32/DriverStore/FileRepository/acpibridge1.inf_amd64_*/InsydeDCHU.dll：
`470D96CAE14FEF2823330C63EA683CF87CB0F6984DC4EB86D21420FF71BE3299`。

回退本机 ControlCenter/DCHU/InsydeDCHU.dll：
`D385DEF14C5AA6CBB8EB60FD34D0EFEB92EAF39E875AB28DE05FE0FDAA7CAB9C`。

两种x64库均静态核对相同接口ABI，并在目标机执行了娱乐档往返。全部加载使用绝对路径和受限搜索标志。遥测工作进程仅绑定Get；模式工作进程在显式事务前不绑定setter。原生缓冲区前后保护页与哨兵检查，异常会停止通道。进程隔离不保证任意固件命令安全，因此不提供任意编号入口。

## 构建与检查

.NET 8 SDK、Windows x64。WinUI包固定1.8.260803003，Windows SDK BuildTools固定10.0.26100.4654。自包含发布无需额外安装Windows App Runtime。

```powershell
.\build.ps1
# 或指定SDK：
.\build.ps1 -Dotnet 'C:\path\to\dotnet.exe'
dotnet run --project .\Diagnostics\KClevoPanel.Diagnostics.csproj -- --self-test
```

发布需保留所有运行库、Assets、KClevoPanel.TelemetryWorker.exe、KClevoPanel.PresetWorker.exe及KClevoPanel.FanWorker.exe；不要只复制主EXE。源码编译产物默认放在work/build，可用X17BuildRoot修改。

开发诊断（在发布目录运行）：

```powershell
# 只读：两路运行时曲线、实际接口库、写入计数
.\KClevoPanel.FanWorker.exe --inspect
# 只读：状态、四档计划、实际加载库、写入计数、待恢复事务
.\KClevoPanel.PresetWorker.exe --inspect
# 只测试日志解析，完全不加载硬件接口
.\KClevoPanel.PresetWorker.exe --self-test-journal
# 明确执行：从性能短暂切娱乐并恢复性能；要求基线和身份全部匹配
.\KClevoPanel.PresetWorker.exe --roundtrip entertainment --apply
# 明确执行：核对未完成日志，重算白名单基线载荷并恢复，不接受任意文件/命令
.\KClevoPanel.PresetWorker.exe --recover --apply
```

若没有未完成日志，恢复命令不写入。若日志不完整或恢复条件不符，则拒绝写入并报告，需要人工核对；不要删除日志后强行继续。恢复应答/记录不等于功耗效果实测。

`KClevoPanel.exe --smoke-test C:\absolute\output` 打开真实窗口并验证只读数据、图表、主题、托盘、硬件布局，保存本程序XAML预览和JSON后退出；模式切换请求数应为0。预览采用不透明主题背景，不表示桌面实际Mica/Acrylic材质。测试预览不捕获其他窗口。普通运行不截图或自动保存遥测。

原厂完整预设还包含按机型分支的ACPI命令79、GPU和Windows策略。后续若加入这些操作，需要分别核对本机条件与效果；当前不把它们混入四档接口。
